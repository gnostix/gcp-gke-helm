File tour — modules/gke/

FileWhat it teaches
iam.tfA custom node service account. The default (Compute Engine SA) has Editor, which every pod could borrow. Ours gets only container.defaultNodeServiceAccount (logs, metrics) + artifactregistry.reader.
main.tf · clusterlocation = zone makes it zonal. remove_default_node_pool + initial_node_count = 1 is the standard trick to manage nodes separately. deletion_protection = false lets the lab be destroyed.
main.tf · dynamic "private_cluster_config"A block rendered 0 or 1 times. With the cheap profile (enable_nat = false) it's omitted and nodes get public IPs. Flip NAT on and you get private nodes.
main.tf · control_plane_endpoints_configTurns on the DNS-based endpoint: access is checked by IAM, not source IP. GitHub's runners have random IPs, so this is what makes Helm-from-CI possible in Step 5.
main.tf · lifecycle { ignore_changes }The cluster-level node_config only shapes the throw-away default pool, so it's ignored afterwards to avoid permanent diffs.
main.tf · node poolSeparate resource: change machine type or add a GPU pool later without touching the control plane. GKE_METADATA hides the node's credentials from pods (needed for Workload Identity).

terraform.ymlNew guard github.ref == 'refs/heads/main': manual runs on feature branches can plan but never apply.

Cost

Control plane: $0.10/h, fully offset by the free tier's $74.40/month credit, which covers one zonal or Autopilot cluster per billing account.
Node: one e2-medium Spot VM plus a 30 GB standard disk. This is the main running cost, so destroy at the end of the day.
Logs/metrics: system components only, Managed Prometheus off.
Spot caveat: Google can reclaim the node at any time. Auto-repair brings a new one, and pods restart. Fine for a lab, and a useful preview of preemptible batch nodes for Slurm-style jobs.

Check your understanding

Why zonal and not regional?

Regional = control plane replicas in 3 zones and node pools spread across 3 zones (3× nodes). Better availability, but the cluster fee isn't covered by the free tier, and node cost triples. For Pfizer production: regional control plane, but batch node pools can still be zonal (cheaper, and HPC jobs usually want co-located nodes anyway).

What does GKE_METADATA protect against?

Without it, any pod can call the VM metadata server and get the node's token. With it, pods only get credentials for the Google SA their Kubernetes SA is bound to (Workload Identity, Step 4), or nothing.

Why does the CI SA need iam.serviceAccountUser?

Creating VMs that run as gke-lab-nodes means "acting as" that SA. GCP requires the deployer to have actAs on it, or anyone who can create VMs could escalate to any SA's permissions.

What would you add for the Slurm migration?

Extra node pools per workload class (high-mem, GPU with taints), cluster autoscaler with scale-to-zero, Spot for batch pools, Kueue or Batch for job queueing, and Filestore/Parallelstore CSI for shared POSIX storage.
